# Stakeholder Identification

*Monilog - Smart Financial Tracking & Analytics Tool*

## Introduction

This document identifies the key stakeholders involved in or affected by the Monilog system, together with their interests, responsibilities, and influence.

## Stakeholder Categories

The project groups stakeholders into four categories:

- primary stakeholders
- secondary stakeholders
- technical stakeholders
- external stakeholders

## Primary Stakeholders

### Individual Users

**Description:** People who use the system to track personal income and expenses.

**Needs:**

- fast transaction entry
- clear financial summaries and analytics
- reliable and easy-to-use interaction

### Chat-Based Users

**Description:** Users who primarily interact through the WhatsApp chatbot.

**Needs:**

- natural and flexible message input
- quick response times
- accurate interpretation of messages

## Secondary Stakeholders

### Power Users

**Description:** Users who need more control and deeper insight into their financial records.

**Needs:**

- stronger filtering and categorization
- richer analytics
- better record management

### Web and PWA Users

**Description:** Users who rely on larger-screen reporting, browser access, or installable desktop-like usage.

**Needs:**

- stronger visualization
- detailed reporting controls
- export and management tools
- reliable offline behavior

## Technical Stakeholders

### Project Owner / Developer (Lespa)

**Responsibilities:**

- define the product direction
- build and maintain the system
- keep the architecture scalable and maintainable

**Needs:**

- clear requirements
- clean documentation
- efficient development workflow

### Backend System Team / Platform Layer

**Responsibilities:**

- process and store transaction data
- support analytics and chatbot flows
- enforce security and reliability

**Needs:**

- high reliability
- secure data handling
- scalable service design

## External Stakeholders

### WhatsApp / Messaging Platform Providers

**Interest:** Enable and deliver chatbot communication.

### Cloud and Hosting Providers

**Interest:** Support database, backend, file storage, and deployment needs.

### Authentication Providers

**Interest:** Support secure sign-in flows, including possible federated login.

## Stakeholder Summary

| Stakeholder Group | Primary Interest | Influence |
| --- | --- | --- |
| End users | Easy and reliable finance tracking | High |
| Chat users | Fast conversational logging | High |
| Power users | Richer reporting and control | Medium |
| Project owner | Delivery quality and scalability | High |
| External providers | Stable integrations and usage | Medium |

## Conclusion

Monilog should be designed first around end users and chat-based users, while still leaving room for technical scalability and richer browser-based workflows.
